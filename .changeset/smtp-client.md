The client, as `@bumail/smtp/client`. `sendMail(message, options)` delivers one message to a host (`{ host, port }`: a smarthost, submission on 587 or 465 with `secure: true`, a local Mailpit) or to a domain's mail hosts (`{ domain, resolver }`): its MX records by preference, its own address without MX, a null MX (RFC 7505) refused at once, the next host tried after a temporary failure before MAIL FROM. STARTTLS is opportunistic by default (RFC 7435, the certificate not checked) and `required` — the certificate checked against the host name, `ca` to trust more — with `auth` or `secure`; EHLO again after it, HELO after a 5xx to EHLO. AUTH PLAIN and LOGIN go out only once encrypted, unless `allowPlaintextAuth` for a local test server. MAIL FROM carries SIZE, `BODY=8BITMIME` and SMTPUTF8 as the server offers and the message needs; MAIL FROM and RCPT TO are pipelined when offered (RFC 2920). The message is a string, bytes or a `ReadableStream`, dot-stuffed as it is sent; a bare CR or LF is refused with `BARE_LINE_BREAK`, or made CRLF with `normalizeLineEnds`. It resolves to `{ accepted, rejected, reply, host, port, tls, authenticated }`, and rejects with an `SmtpError`: new codes `CONNECTION_FAILED`, `TIMEOUT`, `BAD_REPLY`, `REFUSED`, `RECIPIENTS_REFUSED`, `TLS_UNAVAILABLE`, `TLS_FAILED`, `AUTH_UNAVAILABLE`, `EXTENSION_MISSING`, `NULL_MX`, `DNS_FAILED`, and on every error `temporary`, plus `reply` (enhanced status code included) and `rejected` where they apply. Each step has RFC 5321 §4.5.3.2's timeout for the whole wait (a stalled message stream included), shorter if asked and at most 2 147 483 seconds, under an overall `deadline`; a reply line is 2048 bytes at most, a reply 100 lines, a session's replies 1 MiB, each read in one pass. `resolveMx(domain, resolver)` is exported too. MX delivery takes any resolver with `mx`, `a` and `aaaa` (`MxResolver`, declared by shape, which `@bumail/dns`'s `Resolver` fits), so neither entry nor its declarations import `@bumail/dns`, and it is no peer: install it for a resolver. By MX, `helo` is required (the machine's name is rarely a fully-qualified name that resolves back), and at most 10 hosts are looked up, every lookup under `deadline`. `auth` goes only with `tls: 'required'` unless `allowPlaintextAuth`: with `'none'` or `'opportunistic'` it is `INVALID_OPTION`. A message stream ending in a bare CR is refused like any bare line break, before the dot.
