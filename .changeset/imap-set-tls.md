`server.setTls({ key, cert })` takes a renewed key and certificate without a restart: the next STARTTLS upgrade and the next implicit TLS connection use it, with or without `proxyProtocol`, and the sessions already open keep the TLS they have. The pair is read (a `Bun.file` included) and checked as a TLS context first; one that cannot be used rejects with `ImapError` `INVALID_OPTION` (`setTls(): tls: { key, cert } cannot be used: …`) and the old pair stays in use; so does an empty key or certificate, which is refused the same way. `listen()` now refuses an empty key or certificate too (`listen(): tls: { key, cert } cannot be used: the key is empty`, or `the cert is empty`), where it was accepted before. Calls apply in the order they were made, so the later call wins however slowly the earlier one reads its files. To make this possible, implicit TLS without a proxy now listens in clear and upgrades each socket to TLS as it opens (`socket.upgradeTLS`, as STARTTLS does) with the pair in use then, because a native `Bun.listen` TLS listener keeps the context it was created with.
