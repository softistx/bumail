# @bumail/acme

## 0.2.0

### Minor Changes

- [#59](https://github.com/softistx/bumail/pull/59) [`60d0c74`](https://github.com/softistx/bumail/commit/60d0c74a4838ef553d38fcdb3934e0c020a185a8) Thanks [@SteveGT96](https://github.com/SteveGT96)! - The ACME client (RFC 8555), still with no dependency and no required peer. `new AcmeClient({ directoryUrl, accountKey, fetch? })` fetches the directory once and keeps it; keeps each answer's `Replay-Nonce` for the next request and fetches one by a HEAD to `newNonce` only when none is left; retries a `badNonce` refusal with the nonce it carries, 3 times at most; and offers `newAccount({ contact, termsOfServiceAgreed, onlyReturnExisting })` (the account URL, kept as `kid`), `newOrder({ identifiers })`, `order(url)`, `authorization(url)`, `challenge(url)` (POSTs `{}`), `waitForAuthorization` and `waitForOrder` (polling as `Retry-After` says, clamped from `pollIntervalMs` to a minute, within a `timeoutMs` and an `AbortSignal`), `finalize(order, csr)` and `certificate(url)`, the PEM chain, each certificate in it parsed and issued by the next. Every fetch is a POST-as-GET. Every URL, given or answered, must be `https:` (`allowInsecure` takes `http:`, for a test CA only); a redirect is refused; answers are read up to 256 KiB, a certificate chain up to 1 MiB; every number from the CA is clamped; the account key appears in no message and no `inspect`. `obtainCertificate({ client, names, certificateKey, http01: { set, remove } })` runs the whole HTTP-01 flow: it refuses an order or an authorization for other names than asked, and a certificate whose leaf is not for `certificateKey` and exactly those names, or has expired; and it always removes the tokens it set, even on a failure, an abort or a timeout, each once its `set` settled, all within one grace, a cleanup failure going in the `cause` of the error thrown: it replaces the cause of a `TIMEOUT` from `timeoutMs` or of an `ABORTED`/`the signal timed out` from the caller's signal, and becomes the cause of any other `AcmeError` without one; it is lost for a hook's own error that is not an `AcmeError`, a `NETWORK_ERROR`, and a request's `no answer within … ms` `TIMEOUT`. `http01Responder()` serves key authorizations from memory as a `Bun.serve` fetch handler, answering 404 to anything else. `AcmeError` gains `problem`, `status` and `retryAfter`, and the codes `NO_ACCOUNT`, `SERVER_PROBLEM`, `RATE_LIMITED`, `BAD_RESPONSE`, `NETWORK_ERROR`, `TIMEOUT`, `ABORTED`, `AUTHORIZATION_FAILED` and `ORDER_FAILED`. `signJws` now also refuses a URL longer than 2048 characters, by the same rule the client checks URLs with. Key rollover, revocation and renewal information (ARI) come later.

## 0.1.0

### Minor Changes

- [#56](https://github.com/softistx/bumail/pull/56) [`6aff91c`](https://github.com/softistx/bumail/commit/6aff91c7c74dadb1b241dac94fc41881f8cc7ade) Thanks [@SteveGT96](https://github.com/SteveGT96)! - A new package, published for the first time: the primitives of an ACME client (RFC 8555), with no dependency and no required peer. `createCsr({ names, keyPair })` builds a PKCS [#10](https://github.com/softistx/bumail/issues/10) request (RFC 2986) for DNS names — the subject `CN=<first name>`, the public key as Web Crypto exports it, an `extensionRequest` holding a `subjectAltName` with every name as a `dNSName` — signed with `ecdsa-with-SHA256` (the P1363 signature turned into DER) or `sha256WithRSAEncryption`, and returns its DER, its PEM and the names; names are checked first (ASCII DNS host names, IDNs as A-labels, no wildcard, no IP address, at most 100). `signJws` signs an ACME request as a flattened JWS (RFC 7515) with the protected header `{ alg, nonce, url, jwk | kid }`, ES256 or RS256, and the empty payload of a POST-as-GET. `jwkThumbprint` (RFC 7638), `publicJwk`, `keyAuthorization` and `http01Path` answer HTTP-01. `generateKeyPair` makes a P-256 or RSA-2048 pair, `exportPrivateKeyPem` writes the private key as PKCS [#8](https://github.com/softistx/bumail/issues/8) PEM that Bun's TLS takes, and `importKeyPairPem` reads it back. Every refusal is an `AcmeError` with a code: `INVALID_NAME`, `INVALID_OPTION`, `INVALID_KEY` or `INVALID_TOKEN`.
